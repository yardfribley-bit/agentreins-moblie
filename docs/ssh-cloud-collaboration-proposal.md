# X 小助手：SSH 与手机、云端协作（待实现）

## 目标

手机负责 X 和其他 Android 应用的界面操作、状态展示及人工接管；远程主机负责用户授权的服务器任务和持久执行。两者用任务 ID、设备 ID、事件序号关联，记录来源、状态、可查看结果和失败原因。现有 Relay 接口可评估复用，但不能假定已支持通用服务器接入。

## 第一阶段：单台主机

1. 用户建立主机配置：名称、地址、端口、用户名，优先密钥认证。私钥留在设备安全存储，禁止进入提示词、任务日志、笔记和截图。
2. 首次连接显示服务器主机密钥指纹，由用户通过独立渠道核对；变更时暂停并提示，不自动接受。
3. 连接测试后先完成一条低影响、可检查的只读任务，展示命令、目标主机、退出码和输出；输出需有长度上限，可能含敏感信息时避免自动回传模型。
4. 明确超时、取消、断线与后台进程的真实状态；连接断开不等于服务器任务已停止。用户能查看及停止任务。

## 第二阶段：协作与接管

- 任务中心记录可恢复状态、幂等键、事件序号和设备租约，避免重连重复发帖或重复执行。
- 任务消息与文件附件分离；采用认证、加密传输和访问控制。模型只获得完成任务所需的内容，不传播密码和令牌。
- 用户接管手机操作时进入同一设备的当前会话；SSH 会话与手机屏幕操作状态分别显示。
- 服务器任务的权限、风险确认、审计、输出过滤、过期及清理策略先设计再执行；不默认给模型无限 shell 权限。

## 待验证

- 选用 Android 可维护的 SSH 实现，核验算法支持、主机密钥校验、许可证和密钥库兼容性；研究 DSH Go 实现时遵守其 AGPL 许可证，避免未经评估复制代码。
- 在测试主机验证指纹确认、密钥连接、进程断线、取消、输出截断、敏感信息脱敏及多任务互斥。
- 检查 Relay 是否满足鉴权、持久化、重放与文件大小需求，再决定扩展或新增协议。
