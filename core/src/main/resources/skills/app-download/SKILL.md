## 先确定来源和目标

- 先确认用户指定的应用、官方链接或仓库；有同名应用时核对开发者、包名或官方站点，不能确定就询问。用户指定可信来源时先检查它。
- 国内常见应用优先查看手机实际可用的官方应用市场；国外常见应用可优先检查实际可用的 Google Play。实际以开发者的官方渠道、应用是否上架以及手机可访问情况为准，不能假定商店已安装、已登录或有网络。
- 商店没有时找开发者官网或其明确链接的官方发布渠道；开源项目查看用户指定或经官网确认的 GitHub 仓库 Releases。搜索结果和第三方页面仅作线索，不能据此认定官方下载地址。

## 核对版本和文件

- 读取实际发布页面，核对项目名、版本号、发布状态、日期及 Android 下载附件。最新版正式版和较新的预发布或测试版分别标注；不要仅凭版本号、页面顺序或仓库源码提交时间猜测。正式版不存在或没有 Android 附件时如实说明。
- 如果用户要求列版本或选择版本，展示实际查到的选项、正式/测试标记、发布时间、附件名称和来源链接，等待用户选定后再下载。用户指定某个版本就查该版本；用户要求最新版但未指定测试版时优先推荐最新正式版，若只有测试版，说明并询问。
- 核对 Android 版本、CPU 架构及附件说明；优先匹配本机的 APK 或开发者明确说明的 universal APK。不能确定架构、文件类型或安装方式就说明，不把源码压缩包、AAB 或拆分包当作普通 APK。
- 如果能核对安装包校验值和签名就核对；不能核对的标为未验证。更新已安装应用时，签名或包名不兼容须说明，未经用户明确要求不要卸载旧版或清除数据。

## 下载、确认与失败处理

- 从实际读到的官方附件链接操作；内置浏览器下载后用 web_downloads 检查完成状态。商店安装则观察系统或商店的实际结果。文件已下载、安装界面已打开和安装完成是不同状态；不能用点击代替完成证明。
- 访问失败先区分登录页、网络错误、权限、文件不存在或设备不兼容；记录可见错误。同一无新信息的路径不要反复重试，说明阻碍及可选的官方路径。不要猜测代理地址或安装完成。
- 用户要求列版本但未选择时暂停；购买、授权和系统要求本人操作的步骤交给用户。报告已核实的来源、版本、文件及完成状态，缺失信息写未确认。
