# agentreins-moblie

[简体中文](README.md) | English

An Android AI assistant for app automation, browsing, files, and continuous live-stream listening followed by requested text replies.

This is a customized fork of [Mika](https://github.com/wangzan101/Mika). Original copyright and Apache-2.0 notices are retained. Added features include live-audio transcription, personal OpenRouter provisioning, and standardized APK filenames. Upstream demos are not device validation of this fork.

## Version and installation

Current version: **0.1.14, build 15**. The application label and assistant identity are agentreins-moblie. The internal package remains com.wangzan101.mika for compatibility with existing configuration and data.

APK filenames are generated automatically:

```text
agentreins-moblie-v<version>-build<versionCode>-<variant>.apk
agentreins-moblie-v0.1.14-build15-debug.apk
```

Public repository: [yardfribley-bit/agentreins-moblie](https://github.com/yardfribley-bit/agentreins-moblie). Personal preconfigured APKs remain local under app/build/outputs/apk/debug/ and are not uploaded because they contain personal credentials. No public APK has been released; build an ordinary version from source and enter your own key.

The test APK uses a debug signing key. A signature mismatch prevents replacing an upstream installation. Do not uninstall an existing installation without considering its local data.

## Capabilities and requirements

- Background app automation using a virtual display, accessibility, OCR and optional vision.
- Built-in browser with page interaction, uploads, downloads and persistent website sessions.
- Continuous audio capture and transcription in approximately eight-second chunks, consumed by the agent while it operates the phone.
- Scheduled tasks, local preferences, execution records and task interruption or handover.
- Local Linux sandbox for Python, Node and shell; networking is disabled by default.

Installation requires Android 11+. Background phone automation requires Android 13+, with Android 14+ recommended. The sandbox requires arm64. Phone automation needs wireless-debugging pairing and accessibility; cloud models need network connectivity.

## Quick start

1. Install this fork's APK.
2. Complete the phone-operation setup wizard. See the [setup guide](docs/setup-guide.en.md).
3. Check Settings > Models. A personal build seeds the OpenRouter defaults below; ordinary builds require manually configured credentials.
4. Try a simple phone task first, then enable live listening separately. Installing or opening the app never starts recording automatically.

## Live listening and replies

1. Turn off Settings > During work > Mute the app being used. Stop an existing task first if it has already muted Douyin.
2. Open Settings > During work > Live listening. The personal build preconfigures its transcription URL, model and key.
3. Choose the audio source, start listening and accept Android's permission prompts.
4. Check the latest transcript displayed on the setup page before starting replies.
5. In a new chat, request continuous listening and relevant short replies. State the intended duration and reply rules.

Internal capture only targets the standard Douyin Android package com.ss.android.ugc.aweme. App or system policy may produce silence; cloned apps, Douyin Lite and internal browser audio are not included. Huawei and some other OEMs can block internal playback capture even while Douyin is audible. If internal capture stays silent for about 24 seconds, that session switches to the microphone, remembers the choice, and needs speaker playback. Turn the microphone switch off and start again to retry internal capture; silence switches back once. Microphone mode may capture nearby people as well. It does not flip back to internal capture on its own.

Stop capture from the notification or listening page. Ending a task also stops a session it has claimed. Stopping capture does not retract sent messages; stop the phone task too if it is still running. Sessions last up to one hour. Before a chat task claims listening, the two-minute idle stop does not apply. After it claims the session, two minutes without a read stops capture. Restarting from Settings starts a new session; the same chat attaches on its next listen.

Fixed chunks can split sentences. Reply timing, deduplication and a suggested 15-second interval depend on model instructions and are not enforced by the send layer. See [live-audio details](docs/live-audio.md).

## Build and personal credentials

Use JDK 17, an Android SDK and network access for dependencies:

```sh
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug
```

APKs are written under app/build/outputs/apk/debug/ with the generated filename.

For a personal build, set openrouter.apiKey in the ignored local private-build.properties file, or use AGENTREINS_OPENROUTER_KEY in the build environment. The environment variable takes priority. No real key is included in source or documentation. Without injection, builds use ordinary manual setup.

**An injected key is still extractable from the APK. Personal builds must not be publicly shared.** Runtime credentials are stored with Android Keystore encryption. See [private-build notes](docs/private-build.md).

## Validation and limitations

Local compilation, unit tests and APK signature verification passed. OpenRouter text, vision/tool calling and transcription requests succeeded. The customized audio workflow has not been validated on a connected physical Android device; capture compatibility, background operation and actual Douyin replies still require testing.

Final-answer review is currently disabled, affecting dependent learning flows. See the inherited [roadmap](docs/roadmap.md). Default Ask mode only confirms spending steps; sending messages, submitting forms and deleting data can execute directly.

## Privacy, updates and attribution

There is no project backend. Model requests go to configured services; with OpenRouter they are routed to the corresponding providers and billed by those services. Audio is buffered in memory without recording files; transcripts enter task history. Conversations, execution records and settings are primarily local.

The inherited update checker still points to upstream Mika. There is no separate update feed for this fork; upstream releases do not contain these local changes.

The [architecture](docs/architecture.md) and [roadmap](docs/roadmap.md) primarily describe the inherited framework. Customized audio and provisioning are covered in the linked feature documents.
