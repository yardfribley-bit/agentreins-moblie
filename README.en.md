## What it can do

- Compare a price in one sentence. It searches the same product in shopping apps, one app after another, and only reads the price. You can change which apps in Settings, or name a few in the chat.
- Use your own Obsidian folder as the knowledge base. Before a task it reads related notes. After a success it writes back. The chat shows which notes were read and which were written.
- After the background screen is set up, the assistant taps apps on a second screen that does not take over yours. You can keep using your phone.
- Join one Hub session, send task progress there, and run instructions from the person who owns that session.
- Speaking aloud stays off until you allow it. While it speaks you see a prompt, and you can stop it with one tap.
- It can also read web pages, work with files you give it, post, or look things up, when you ask.

## Three steps to start

Do this on the phone. You do not need a computer, and you do not run adb on a computer.

1. Download the APK from [Releases](https://github.com/yardfribley-bit/agentreins-moblie/releases). If nothing is there yet, open a successful Android build on [Actions](https://github.com/yardfribley-bit/agentreins-moblie/actions) and download its debug APK. The repository does not include a model key.
2. Open the app and follow the guide. For the model, DeepSeek is the recommended path: on the phone, open [API keys](https://platform.deepseek.com/api_keys) and paste the key. Saving tries the model once and keeps it only if that works. Then turn on accessibility for X Assistant. You can pick a knowledge-base folder here, or skip it; the screen says what you lose.
3. Try one sentence. The last guide step is a sample that only talks to the model and does not operate the phone. After that you can type your own, such as “compare the price of milk”.

The background screen is an optional extra. Chat, web pages, and files do not need it. Price comparison and tapping apps do. That step is wireless debugging in the phone’s developer options. The guide walks through it on the phone. Accessibility alone cannot create this screen.

## Safety and what you can see

- Price comparison is read-only. It does not add to the cart, place an order, claim a coupon, or sign in. A login wall is recorded, then it moves to the next store.
- Paying asks you on the phone first. Instructions from the Hub owner do the same for payment, transfers, deletion, messages to other people, and typing a password.
- Speaking aloud stays off until you allow it. While it speaks, the screen shows that, and one tap stops it.
- Each task shows which knowledge-base notes it read and wrote. You can also open the sources used for an answer.

## Common questions

**Why wireless debugging?**

Android only allows that second screen through wireless debugging. Accessibility is how the assistant sees and taps. Both happen on the phone. You do not need a computer. Chat, web pages, and files skip this. The pairing code expires in about a minute; ask for a new one if it does.

**What if I have no model key?**

Create one at DeepSeek and paste it into the model step. If saving fails, check that the key was copied in full, or pick another provider from the list above and try again. Tasks that need a model cannot start until one works.

**What does price comparison need from the phone?**

It uses one background screen and checks stores in order. It does not open several shopping apps at the same time. Install the apps you want checked; a missing app is recorded as not found, and no price is invented. The app installs on Android 11 or newer. The background screen also needs accessibility and the wireless-debugging pairing above. Several screens at once is not how price comparison works today.

**Do I need an Obsidian plugin?**

No. Pick or create a folder in the app. Notes are written under an AgentReins subfolder inside it, and your existing pages are left in place. You can open that same folder in Obsidian if you want to read it there.

## For developers

You need JDK 17 and an Android SDK. From the repository root:

```sh
./gradlew :app:assembleDebug
```

The debug APK is written under the app module’s build output, and the file name includes the version. Pushes to main, and pull requests into main, run the Android build on GitHub Actions and attach that debug APK to the run.

Main directories: app is the phone UI, core is tasks and tools, docs is the longer notes, and .github/workflows is the build above.

Send changes as a pull request to [this repository](https://github.com/yardfribley-bit/agentreins-moblie).
